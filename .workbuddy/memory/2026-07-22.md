## 贴图"彩虹噪点"——真正根因与修复（01:0x，背面剔除）
- **误诊过一次**：先以为是 2048 无 mipmap 的缩小采样失真，加了 mip 链（保留，无害有用）但**没解决**。
- **真正根因（实锤）**：模型表面彩虹噪 = **双面渲染没做背面剔除**。RE 网格**每个面发了前后两份（约 18% 重复面）**，两面片重叠 z-fight，相邻像素命中不同面采到不同 UV 区域 → 斜向条纹噪。之前 512+0.75+平滑放大把噪点糊成了"棕色糊"（用户当时以为是"糊"），提分辨率后原形毕露。
- **验证过程**（诊断程序 `src/DiagSkinning`，复刻 GUI 透视相机渲染实测）：albedo 贴图本体正常（深色布料+红）、UV 平滑正确（渐变图无错乱）、贴图-面映射全是 albedo、UV 在[0,1]。**保留 d>0 绕序做背面剔除 → 渲染出完整干净模型**（肤色手臂、深色外袍、红内衬）；d<0 是内侧/背面。
- **修复**：`Viewport3D.RasterTriangleInto` 在退化检查后加 `if (BackfaceCulling && d < 0f) return;`，并加 `public bool BackfaceCulling { get; set; } = true`（可关��。**前次"剔除掏空"是绕序符号弄反了**（错留 d<0），本次 d>0 才是朝前。
- **关键教训**：RE 模型双面靠"前后两份重复面"实现，软件光栅**必须配背面剔除**（屏幕空间绕序），否则两面互抢深度出噪。绕序符号要用渲染实测来定，别凭理论猜。

## 贴图"彩虹噪点"修复（00:2x，mipmap）
- **症状**：③改完贴图后整个模型表面变成彩虹噪点（用户截图）。根因：贴图提到 2048 后软件光栅**没有 mipmap**，高分辨率贴图缩小到屏幕小区域时**每像素覆盖大量 texel → minification aliasing**。之前 512 那种"糊"其实是接近屏幕分辨率的低失真状态。
- **修复**：给 `ViewportTexture` 加 mip 链（`Mips/MipW/MipH`，`DecodeTexture` 里 `BuildMipChain` box 滤波 2x2 逐层减半到 1x1）；光栅器 `RasterTriangleInto` 逐三角形按 `rho2 = |duv|*tw*th/|d|`（每像素覆盖 texel 数平方）选 mip 层（`0.5*log2(rho2)`），双线性在该 mip 层采样。近景用 level0（2048 清晰）、远景自动降 mip（不噪）。
- **教训**：软件光栅提高贴图分辨率必须配套 mipmap，否则高分辨率反而引入缩小采样失真。"贴图糊"和"贴图噪"是同一枚硬币两面：糊=分辨率不足，噪=分辨率高但无 mipmap。
